# v0.1.0 Release Notes

Status: Draft for the initial public release

## What This Release Establishes

`v0.1.0` sets the repository up as a bilingual, pattern-first MCP catalog with a clear editorial boundary:

- three core content lists for servers, workflows, and recipes
- shared editorial docs for evaluation, taxonomy, and submissions
- contribution scaffolding for issues and pull requests
- baseline repository policies for conduct and security

## Included In v0.1.0

- `README.md` and `README.zh-CN.md` to explain repository scope and navigation
- `lists/servers.md`, `lists/workflows.md`, and `lists/recipes.md` as the core catalog surfaces
- `docs/evaluation-rubric.md`, `docs/taxonomy.md`, and `docs/submission-template.md` as shared editorial references
- `CONTRIBUTING.md`, `.github/pull_request_template.md`, and `.github/ISSUE_TEMPLATE/*` for contributor workflow
- `CODE_OF_CONDUCT.md`, `SECURITY.md`, and `LICENSE` as baseline public-repo governance files

## Editorial Position

The first release is intentionally conservative:

- the repository is a curated pattern catalog, not a claim of market share or tool quality
- most entries begin as `Pattern seed` content unless a contributor documents stronger evidence
- trust boundaries, human review points, and honest limitations are part of the content model, not optional extras

## Contributor Expectations

Contributors should be able to:

- propose new patterns through issue templates or pull requests
- use the submission template to keep entries compact and consistent
- distinguish clearly between documented facts and pattern-level inference
- improve navigation, wording, and taxonomy without changing the repository's evidence bar

## Known Gaps After This Release

- More entries still need stronger sourcing before they can move from `Pattern seed` to `Documented example`.
- Maintainer-specific operating docs, such as release process or triage routines, are still light.
- Repository automation is intentionally minimal at this stage.
